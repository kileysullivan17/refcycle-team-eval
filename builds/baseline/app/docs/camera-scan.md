# Camera scan

**Server.** `POST /api/identify` takes `{ "image": "data:image/(jpeg|png|webp);base64,..." }` (5 MB decoded at most; bytes must match the type) and returns `{ status, label, candidates, model }`. The model is asked only what the item is. Only `status`, `label` and `candidates` survive; any stream, verdict or advice the model adds is dropped (CS-4). Unusable output or a provider error returns 502. The image provider is set by `LLM_IMAGE_PROVIDER` and `LLM_IMAGE_MODEL` (defaults `anthropic`, `claude-sonnet-5-5`), temperature 0 where accepted, with the engine's retry-without-temperature behavior. `logs/identify.jsonl` records time, status, label, model and duration only.

**Screens.** `/scan`: live viewfinder with Identify, Photos, Snap Tips, close, flash and flip. If the camera is missing or denied, a photo upload takes its place (CS-9). Photos are downscaled in the browser, sent once, and dropped (CS-10). `/scan/confirm`: "We think this is: <label>. Is that right?" with Yes, Edit and Retake; `multiple` asks which one (or a typed name); `unclear` asks to retake or type. Only a confirmed or typed label goes on, as `/item?q=<label>&origin=scan`. This feature never calls `/api/ask`.
